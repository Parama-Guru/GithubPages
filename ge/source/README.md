# Ganesh Electricals — 3D website source

Source for the site published at `GithubPages/ge/` (`https://parama-guru.github.io/GithubPages/ge/`).
Content comes from the company profile deck (`src/content/profile.json`), the original site (`src/content/site.json`,
`src/content/organisation.ts`) and the client's approved review (round 4; see `../content-brief.md` and
`../client-inputs.md`).

## Commands

```powershell
npm ci                    # install (Node 24)
npm run dev               # http://127.0.0.1:5173/GithubPages/ge/
npm run assets            # regenerate Blender models with baked AO and animations (Blender 4.5 LTS; set BLENDER=path\to\blender.exe)
npm run assets:preview    # render the switchgear and transformer with the colour palette into .cache/look-preview (public/models untouched)
npm run camera            # export the journey camera path from blender/camera_path.blend to src/world/camera-path.json (the world is shown on the home page only, so there are no per-page poses)
npm run media             # favicon, touch icon, the emerald route-change emblem (64/120 px), logo sizes (240/480 px), 520/800 px photo copies and 120/240 px client-logo copies for srcset
npm run build             # typecheck + client build + prerender every page into dist/
npm run serve             # serve dist/ at http://127.0.0.1:4173/GithubPages/ge/ (gzip, like Pages)
npm run posters           # with `serve` running: render the 8 home posters and the home social image from the 3D scene, and the other pages' social images (1200×630) from the pages themselves
npm run publish:local     # copy dist/ into GithubPages/ge/ (keeps source/ and checklist.md)
npm run test:unit         # Vitest: camera maths, routes, content integrity
npm run test:e2e          # Playwright + axe: pages, 3D journey, clicks, navigation, fallbacks, budgets
npm run lint
npm run review:journey    # with `serve` running: screenshots of every chapter hold and transition into .cache/shots
npm run review:pages      # with `serve` running: screenshots of every dedicated page into .cache/pages
npm run review:sheet -- <dir> [filter] [file] [columns] [width]   # contact sheet of screenshots
```

After changing the scene, run `build`, `serve`, `posters`, then `build` again so the posters are included.

## Structure

| Path | Purpose |
|---|---|
| `src/content/` | `profile.json` (company profile deck — the authoritative content), `company.json` (the client-approved About Us, contact details, newsletter text and logo — the small part the first page needs), `site.json` (original site: logos, photos, policies), organisation chart |
| `src/routes/routes.ts` | Clean URLs, titles, descriptions, zones |
| `src/ui/` | HTML templates shared by the prerender and the client router |
| `src/app/` | Motion (Lenis + GSAP), home journey, page controller, tour position for Back (`tour.ts`), preferences, sound |
| `src/world/` | Three.js runtime: camera path, zones, materials, textures, shaders, post-processing |
| `blender/build_assets.py` | Switchgear, entrance doors, transformer, insulator string and lattice tower (baked AO, door/breaker animations; colours from `src/world/look.json`) |
| `blender/camera_path.blend`, `camera_path.py` | Camera keys for the scroll journey and every page, edited in Blender |
| `tools/` | Prerender, publish, static server, Blender/asset build, poster and screenshot tools |
| `tests/` | Unit and browser tests |

## Assets

All 3D models are generated by `blender/build_assets.py` (own work); textures inside models are WebP, geometry is meshopt-compressed. Textures, signs, screens and the
organisation board are drawn in code. Photographs, logos and client logos are from the original website.

## Typography

The owner kept the cursive accent and asked for the other fonts to change (round 4). Two families plus the script
accent, all self-hosted from Fontsource (Latin subset only; `src/styles/fonts.css` declares Spectral and Hanken Grotesk,
`src/main.ts` imports Parisienne). The pairing was chosen from five serifs rendered with Hanken Grotesk and Parisienne
on the ivory card: Spectral was the brightest and most precise (also the display serif of Arup's site); Newsreader was
heavier to download, Playfair read like a wedding card next to the script, Noto Serif Display thinned out at 22 px.

| Role | Font | Where it is used |
|---|---|---|
| Display (`--font-display`) | Spectral 500 (one static weight declared for 400–700, so no faux bold) | Hero, chapter, page and section titles, menu links, statistics, years and figures; 3D plaques, stat screens, principles screen, quality board and project-group signs |
| Body (`--font-sans`) | Hanken Grotesk Variable | Reading text, navigation, buttons, forms and tables; 3D plaque text, documents plate and organisation board |
| Labels (`--font-mono`) | Hanken Grotesk Variable, weight 600, tracked uppercase (no monospace) | Small technical labels: chapter numbers, tags, table heads, captions, stat-screen captions |
| Script accent (`--font-script`) | Parisienne | Only short accents: the hero's second line "Electricals", chapter and section eyebrows, policy signatures, the footer's "Since 1997" and the "Projects" sub-label of the 3D project-group signs |

Rules: titles are mixed case (no forced uppercase); script never sets body text, buttons, tables or anything below
26 px. SplitText keeps script words whole (`.title-script` is passed to `ignore` in `src/app/journey.ts`) so the letters
stay joined, and its line masks reach 0.3 em below the line so serif descenders are not clipped (`RISE` hides them when
the title animates out). Canvas text uses the `fonts.*` helpers and `fitFont()` in `src/world/textures.ts` (labels set
`letterSpacing` for their tracking), and `fontsReady()` loads all faces before the 3D labels are painted. `index.html`
preloads Spectral and Hanken Grotesk (the faces of the first screen); local Georgia and Arial fallbacks are scaled to the
web fonts' metrics (`size-adjust`, `ascent-override`, `descent-override`) so the swap does not shift the prerendered
text. The fonts add about 80 KB (woff2) on a first visit, down from about 114 KB.

## Colour palette

One bright palette for the whole site and the 3D world: **emerald, terracotta and marigold on ivory**. The owner rejected
the earlier white-and-blue (sapphire) palette and asked for a researched combination of colours; the choice came from a web
search of palette libraries, trend reports and brand palettes (November 2026, evidence in `../checklist.md`). Its core is
Color Hunt's "Racing Green & Marigold" palette (deep green, beige, marigold), completed with the terracotta of the Pantone
2026 "Cloud Dancer" pairings and Digisperse's "Diya Lamp" palette, and tuned for WCAG AA. The earlier switchable themes
(Light, Copper, Signal) and the sapphire palette were removed; there is no theme switch.

Where it lives:

- **CSS**: one `:root` token block at the top of `src/styles/main.css` — named colours `--ivory`, `--paper`, `--emerald`,
  `--emerald-deep`, `--forest`, `--terracotta`, `--terracotta-deep`, `--marigold` and the semantic tokens built from them
  (`--accent`, `--accent-strong`, `--eyebrow`, `--figure`, `--chip`, `--chrome*`, `--header-*`, `--footer-*`, …).
- **3D world**: `src/world/look.json` — room surfaces and their canvas-texture tones, trims, light strips, floor light pools,
  point-light tints, energy flow, the inks of every canvas sign, plaque, screen and board, and the Blender model materials —
  and `src/world/palette.ts` (sky, sun, fog, hemisphere light, exposure, bloom, vignette). Every tier uses Khronos neutral
  tone mapping (in post-processing on desktop and in the posters, in the renderer on phones), which keeps the brand colours;
  the low tier keeps its own sky values. Rooms have polished dark stone floors (`floor` `#655A51`, `floorDark` `#48514B`),
  warm clay walls over a deep green wainscot with a copper rail (`room()` in `src/world/kit.ts`), dark ceilings, contact
  shadows and coloured light pools. The terracotta furniture finish is the
  `lacquer` surface (formerly `navy`).
- **Blender**: `blender/build_assets.py` reads the same `look.json` for its named materials. The site recolours those
  materials when a model loads, so changing the palette needs no model rebuild; `npm run assets:preview` checks the result.
  The small switchgear meter displays (`MeterGlass`) glow jade (`energy.cool`, set when the model loads).
- **Logo**: the original logo is white. The header, menu bar and footer are forest-green bands, so they show the original
  white logo unchanged; `npm run media` cuts an emerald copy of the emblem from its alpha mask (identical shapes) for the
  ivory route-change curtain and makes the favicon and touch icon (white emblem on emerald). The 3D façade and lobby signs
  keep the white logo on emerald plates, with a marigold glow on the façade; the façade sign is painted once, fully and
  steadily lit (no reveal sweep or flicker).
- **Text over the scene**: chapter and page-hero text sits on a compact frosted ivory card (90 % ivory, backdrop blur)
  sized to the text with CSS anchor positioning (`src/styles/main.css`, World); each chapter's card fades with its text
  (`--card` in `src/app/journey.ts`). Browsers without anchor positioning get a narrow ivory veil over the text column.

`tests/unit/palette.test.ts` checks that the look defines every surface and Blender material with valid colours, that the
text painted in 3D keeps 4.5:1 contrast, that the brand roles stay emerald, figures terracotta and highlights marigold, and
that no colour of the 3D palette reads as blue; `tests/e2e/palette.spec.ts` checks the bands, logos, nav underline, hero,
labels, figures, buttons, footer links and the emerald emblem in the browser, and axe checks every page. After changing the
palette run `build`, `serve`, `posters` and `build` again (one poster per chapter in `public/posters/`, social images in
`public/og/`).

## Navigation

- The header lists **Home**, About, How we serve, Projects, Clients and Quality & Safety, then Contact and the Menu
  (`headerLinks` in `src/routes/routes.ts`). Home always opens the home page at its start; on the home page Home, the
  logo and the Menu's Home rewind the tour to the top.
- Pages show no breadcrumb trail; the BreadcrumbList structured data stays in the head for search engines. Instead every
  page hero (and the 404 page) starts with **Back**, which returns to the chapter of the home page the visitor left.
  `src/app/tour.ts` records the chapter in view whenever the tour is left (in memory, in `sessionStorage` under `ge-tour`
  and on the home history entry); Back and the browser's Back/Forward buttons jump straight to that chapter. With nothing
  remembered, or without JavaScript, Back opens the home page at the start.
- Each home chapter links to its own page (there are no "Read more" pop-ups). Page changes fade `<main>` out and in
  (opacity and transform only) and keep focus management and the scroll position.
- The Menu (round 5) groups the pages as Company (About, How we serve, How we work, Leadership, Organisation) and Work
  (Projects, Clients, Quality & Safety, Downloads) with Home and Contact below, marks the current page, and has a forest
  brand card (tower drawing, "Since 1997", tagline, click-to-call, email, address). Its one preference is a switch,
  **3D experience** with motion and sound (`ge-3d`): with 3D on, the home page's ambient animation runs and the sound is
  on — a low hum from the visitor's first click, tap or key press (browsers allow audio only after a gesture), door and
  breaker sounds, silent while the tab is hidden. Switching it off reloads the page with the 2D home page (below), which
  reduced motion, Data Saver, no WebGL and 2G connections also get.

## Pages and modes

Only the home page differs between the two modes (round 5, owner: "except home all other pages can have the same … the
pages in the 2D is the finalised one for the 3D also … remove those old code and have a unified one"):

- **Home with 3D** (`has-3d`, added by the inline head script before the first paint): the scroll journey through the
  3D facility (`src/app/journey.ts`, `src/world/`).
- **Home without 3D**: the animated 2D home page (`src/ui/flat.ts`, `src/app/flat.ts`, `src/styles/flat.css`).
- **Every other page, in both modes**: one design and one set of animations (`is-page` on `<html>`, the page rules in
  `src/styles/flat.css`, `initFlat()` plus the page controls in `src/app/page.ts`). In 3D mode the world fades out and
  stops drawing on these pages and resumes on the same canvas at the chapter left; opening a page directly never
  downloads the world, which starts on the way to the home page (its download begins when a link home is hovered).
  Smooth scrolling (Lenis) is used on the 3D home page only.

The 2D design: ivory pages with forest and emerald bands, terracotta figures and marigold highlights on a 12-column grid,
one left edge for Back, eyebrow, title, lead and content, and equal section padding. Line drawings of the power network
(`src/ui/art.ts`): a lattice tower feeds a substation gantry, a transformer and a factory; the lines draw themselves,
current flows in marigold dashes and the factory windows light up. Every page hero has its own drawing (gantry, gauge,
single-line diagram, transformer, factory, shield, org chart, document, tower, and an open breaker on the 404 page).

- The 2D home keeps the eight chapters, their order and ids (so Back works) with a layout of its own per chapter: hero
  with expertise chips and the drawing, introduction with the milestone timeline (the four GST years included), counters
  with the six principles on a forest band, a photo mosaic with the project years, a moving strip of the 12 client logos,
  policy tiles with the credentials, the founder, and an emerald contact band with click-to-call.
- Motion: after a page change the hero rises in sequence (title word by word out of masks, then lead, first section and
  the drawing, which draws itself; on the first load the title stays still for the largest paint); sections reveal in
  sequence, photos wipe in, counters run and the About milestones line fills as it is read; arrows and cards move a little
  on hover. Everything starts from an IntersectionObserver (no layout reads in scroll handlers) and only transform,
  opacity, clip-path and stroke-dashoffset animate. No 3D chunk, model or poster is requested without 3D (the home
  posters sit in a `<picture>` whose `(scripting: none)` source is empty).
- Reduced motion and no JavaScript show every element in its final state. `tests/e2e/flat.spec.ts` and
  `tests/e2e/pages.spec.ts` cover the 2D home and the shared pages (same layout in both modes within 2 px, no world on
  direct entry, no long tasks during page changes, menu accessibility).

## Loading on slow connections

The prerendered page is usable immediately; the 3D world streams in behind it (`bootWorld()` in `src/main.ts`).
Until the scene is ready, each home chapter shows its rendered poster and a 2 px line at the top shows progress;
the canvas then cross-fades in. `World.load()` requests fonts, models, zone code and post-processing together.
Post-processing (`src/world/post.ts`) is a separate chunk that the low tier (phones) never downloads, and
`three-mesh-bvh` loads after the first frame. Data Saver, reduced motion, no WebGL and 2G connections
(`effectiveType` `2g`/`slow-2g`, unless 3D is switched on in the menu) get the 2D site.

## Performance

Measured with Lighthouse 13.6 on the production build served with gzip like Pages (15 Nov 2026, Edge on an AMD Radeon
780M; numbers from the Vite dev server are not representative: it serves unbundled, unminified modules).

| Page | Start (before round 4) | Now (round 5) | Main change |
|---|---|---|---|
| Home, 3D, desktop | performance 67, TBT 3.7 s | 97–99, TBT 59–125 ms | shaders compiled off the main thread; rooms built in short steps |
| Home, 3D, mobile (simulated) | 68, TBT 5.3 s | 79–83, TBT 0.68–0.86 s | same, low tier |
| Home, 2D, desktop / mobile | 99 / 95 | 100 / 99 | lighter start, no WebGL probe, smaller images |
| Other pages, 3D mode | 71–76 (the world loaded behind the page) | 100 | the world is not loaded on these pages |
| Other pages, 2D mode | 98–100 | 100 | same pages in both modes |

Accessibility and best practices score 100 in every mode. While scrolling the whole 3D tour after it is ready there are
no main-thread tasks over 50 ms on desktop (`tools/scroll-perf.mjs`; the worst stall at 4× CPU throttling fell from 2.3 s
to 0.16 s). What changed:

- Shader warm-up (`src/world/world.ts`): `renderer.compileAsync` with `KHR_parallel_shader_compile` compiles every program
  off the main thread before the first frame. Under post-processing one dry run of the composer turns each internal draw
  into `compileAsync` while that pass's render target is bound, so programs are built in the variant they are drawn with
  (the old `renderer.compile` built the scene for the screen and it was compiled again for the render target). The room
  environment (PMREM) is generated the same way. Rooms are built, uploaded (one texture per task, photos decoded off the
  main thread, models decoded in workers) and compiled in short steps during idle time before they appear, and every
  material variant (e.g. the instanced switchgear row and the single hero panel) is compiled too; shader error checks
  are off in production builds (they made the main thread wait for the GPU).
- No throwaway WebGL context: the 2D site never creates one, and with 3D the capability check makes the context on the
  scene's canvas with the renderer's settings, which the renderer then reuses.
- Smaller start: page templates and the bulk of the content load on navigation (prefetched when idle) and the first page
  uses only `company.json`; Lenis and SplitText load only for the 3D tour. Initial script 89 KB → 56 KB gzip.
- Fewer forced reflows: the viewport size is cached for pointer moves and per-frame metrics, the tour measures chapter
  positions only after layout changes, and the journey splits all headings and reads styles before any tween writes.
- Right-sized images through `srcset`: logo, emblem, project photos and client logos (2D home 1.2 MB → 0.4 MB).

Remaining Lighthouse notes, by design: "unused JavaScript" lists `three.core` (the 3D engine is shared by all rooms) and
part of the start chunk (GSAP and ScrollTrigger code paths not run on the first screen); `robots.txt` and the
back/forward cache findings come from the local server and the headless browser, not from the site (see below).

## Known limitations

- GitHub Pages serves a custom 404 and `robots.txt` only from the repository root; `ge/404.html` is used for
  in-site navigation, and `sitemap.xml` can be submitted to search engines directly.
- Frame rate on real phones has not been measured on physical devices; the site lowers quality automatically
  when frames are slow.
